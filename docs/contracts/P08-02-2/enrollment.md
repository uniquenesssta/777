# 自动登记、主体归属与节点加入

## 1. 请求与接口边界

新接口严格解析 JSON；未知字段、重复字段、格式或类型不符均拒绝。UUID 使用规范小写形式；时间为 UTC Unix 秒；秘密为 32 随机字节的无填充 base64url。请求头承载鉴权秘密，不放 URL；日志仅记录路径模板、请求 ID、主体/包 ID、结果码与阶段。新接口体默认上限 64 KiB，超过即拒绝。限速按来源及凭据摘要分别执行，并限制候选登记数量，不能让匿名请求占满账本资源。

所有请求共用 `protocol` 和 `request_id`；写请求另有站点/账本绑定。协议名由对应接口确定，不能用用户提供的角色替代鉴权。下表是 B/C/D 的接口契约；B 已接入路由，C/D 的安装及桌面调用已接入源码，Windows/现场未执行。

| 方法与 `/v1/automatic` 后缀 | 请求者/主要字段 | 成功结果与限制 |
| --- | --- | --- |
| GET `/capabilities` | 无凭据，已校验 TLS | 支持的协议与站点标识；不返回凭据、主体列表或业务数据 |
| POST `/issuer/session` | 发行秘密；issuer_id | scoped issuer 会话，不返回业务会话 |
| POST `/packages` | issuer 会话；完整包记录、登记秘密摘要 | 服务端确认的不可变记录；权限必须在发行者上限内 |
| GET `/packages/{id}` | 所属 issuer 会话 | 清单、状态、用量；无设备秘密、订单正文 |
| POST `/packages/{id}/close` 或 `/revoke` | 所属 issuer 会话；请求 ID | 关闭新增或撤销全部关联授权，幂等 |
| POST `/devices/enroll` | 包登记秘密；package_id、site_id、ledger_id、device_id、device_secret_hash | device_id、subject、delivery、capabilities、epoch、绑定回执；不发明文设备秘密 |
| POST `/devices/adopt` | 原 v1 设备秘密 + 新同角色包秘密；原 device_id、site_id、ledger_id、package_id | 保留原 subject；停用旧设备及旧会话，不停用维护账号；拒绝不同旧设备暗中合并同一主体 |
| POST `/devices/session` | 设备秘密；device_id | scoped device 会话及当前有效权限 |
| POST `/devices/upgrade` | 设备会话和新包登记秘密（独立鉴权头）；新 package_id | 同角色原子改绑并废止旧会话；跨角色返回内部不兼容码 |
| POST `/nodes/permit` | 母版包登记秘密；package_id、site_id、ledger_id、node_id、node_secret_hash | 绑定该候选节点的短期加入许可；不暴露通用旧邀请 |
| POST `/nodes/enroll` | 节点加入许可；同 node_id/摘要 | 加入回执、主机连接及账本、同步协议；无业务会话 |
| POST `/nodes/adopt` | 原节点秘密 + 新母版包秘密；原节点 ID/摘要及站点/账本 | 采用原 peer 身份，不创建第二节点；旧秘密或新包任一无效即拒绝 |
| POST `/nodes/upgrade` | 节点秘密和新母版包登记秘密；新 package_id | 单独变更节点授权并使旧授权失效 |

设备/节点撤销与恢复由受信的本地维护或既有专门维护身份执行，不向普通母版的业务 admin 会话开放。为避免 scope 回退，新凭据不能被旧登录、登记、发行或群集管理接口接受。

错误状态约定：401 凭据无效；403 授权范围/撤销/额度拒绝；409 相同 ID 内容冲突、站点/账本/部署冲突；422 格式错误；426 协议需升级；429 限速；503 暂时不可用。错误不返回秘密。Host 身份变化、拒绝授权不循环发送新登记，转为有上限退避；网络/暂时失败按 2 秒起、最长 5 分钟带抖动重试，尊重 Retry-After。正式界面不呈现这些技术错误。

## 2. 桌面登记状态机

`waiting_for_trust → candidate_saved → enrolled → active`；可恢复中断保留当前阶段；证书/站点冲突、撤销为 blocked，不能回到匿名创建新身份的分支。

- 安装或首次运行先在当前用户保护存储原子写入 device_id、随机秘密、目标站点、包 ID 与稳定 request_id，然后才发请求。请求只提交秘密摘要，后续会话以秘密证明持有。
- Host 同一事务内校验包、额度、创建业务主体和设备绑定、登记计数、回执与审计。设备 UUID 全站唯一，重复 ID 仅在原包、站点、秘密摘要及内容一致时返回原回执；不因同请求 ID 就跳过鉴权。
- 网络丢失响应后复用同候选和请求 ID。包此时到期/关闭仍允许同绑定取回已完成回执，但撤销不得返回可用授权。确认身份和权限成功后才把本地 candidate 标记 active。
- 后续启动使用持久化设备秘密换短会话，不能每次再创建主体。安装升级保留候选、身份、草稿和待提交请求。
- 安装器提权账户与业务用户可能不同：桌面凭据必须由实际业务用户首次运行时创建，不在管理员账户生成后复制 DPAPI 文件。后台创建节点秘密也必须使用后台运行身份。
- 本契约的“每台独立”指每台电脑的每个 Windows 用户安装身份；同一电脑换 Windows 用户不自动共享销售归属。卸载默认保留保护身份。若用户手工删除密钥、换系统或复制用户配置，不能仅凭硬件/IP 找回身份或声称仍是原设备；进入维护恢复边界，不能自动合并历史。

## 3. 销售归属

默认 **每个新桌面身份对应一个新 subject UUID**，保存在现有业务用户体系，以便订单 owner、备注作者及请求 actor 均可解析。sales 的角色永远是 sales；manager 是具有有限业务 scope 的 admin，不是共享后台管理员。

同一设备升级/重装且凭据仍在时保持 subject；两个新设备默认不同 subject，不自动按 IP、电脑名、客户淘宝 ID、微信号或同一发行包合并。客户识别信息用于订单客户归集，与员工销售身份不同。

历史销售人员换电脑、多台电脑确需同销售主体时，由独立维护功能验证原主体及新设备后显式映射并留审计；不把这一步作为普通新安装必填项。不得靠给全员绑定旧管理员解决“看不到历史订单”。销售读/改/导出必须同时满足订单归属与包权限；manager 按其功能授权访问业务范围。

## 4. 后台加入及幂等

母版桌面设备与同步节点是两个身份，分开计数、撤销、保护和日志关联。子版包申请节点许可始终拒绝，即使客户端声称 manager。node_enrollment 授权与普通业务功能复选项分离。

1. 安装器确认本机是否为原主机：核对本地部署所有者、根目录、服务身份、账本、主机角色及可信站点档案，不只比较 IP。在 4.23 确认匹配则复用，不登记“主机自己的从机”。有原独立账本则停止覆盖并记日志。
2. 非主机先保护保存 node_id/随机秘密及进度，再申请 permit。许可有效 30 分钟，仅能绑定该节点摘要/站点/包。主机使用持久化绑定；同节点同包重试返回原结果，过期可在有效包授权下续领同节点许可，不重复占名额。
3. `/nodes/enroll` 验证许可后创建/核对群集 peer。许可不等于拥有全部管理权，只能读取同账本快照、数据块及提交同步 ack。将安装用户得到的许可安全交给后台运行身份，后者才持有节点长期秘密。
4. 授权库和现有 cluster peers 库是不同事务域：先在授权库写 `reserved` 意图，再幂等创建带相同绑定摘要的 peer，再写 `active` 回执。每次同步鉴权必须同时核对授权 active、包/节点未撤销及 peer；只有 peer 行存在不能开放快照。重启按意图续做，身份冲突 fail closed；不得把跨库写入当作原子事务。
5. 初始化下载校验快照、账本身份及协议后原子启用本地副本；只有完整校验并 ack 对应数据代后才记录“同步完成”。未完成时是 pending，不创建独立可写主机。同步节点不重复运行主机每日备份/报表任务。
6. 主机离线保留进度、重试；业务仍连 4.23，绝不自动升主。旧 peer/副本重复安装需凭原节点秘密及部署归属复用，缺凭据的旧节点需明确兼容迁移，不能只凭目录存在或相同主机名冒认。

固定目录及隐藏备份语义沿用任务书，不在登记协议中开放任意路径。无需网络共享 Host/Service/Hidden。副本包含业务数据和授权摘要，能管理同步电脑操作系统的人可能读取本地数据；不能把 UI 权限包装成对本机管理员的加密隔离承诺。

## C/D 接入补充

共享 `777-automatic-package-v1` 封套持有原站点档案、不可变 manifest 和受限登记秘密；不含发行者秘密或维护密码。原生安装内部入口为 `automatic-node-join`；发行内部入口为 `automatic-issuer-status`、`automatic-issue`、`automatic-close`。它们只服务界面/安装编排，普通使用者无需输入命令或定位状态文件。未修改既有协议版本。

旧桌面采用的 Authorization 为原设备秘密，`X-777-Package-Authorization` 为新包秘密；同时核对设备启用、原主体 epoch、delivery 与站点。成功后旧设备会话失效，重复采用凭原秘密只允许取同绑定回执。原维护账号密码保留。旧多设备共用一个主体的历史不能自动合并成独立新身份，冲突进入维护范围。

新节点身份由 SYSTEM 后台任务本身产生；原节点继续原账户。桌面原生重试门控制网络请求速率，UI 轮询不绕过退避；后台 runner 每次失败按状态退避，同一候选/身份不变。服务端 Retry-After 采用 delta-seconds，客户端接受不超过 86400 秒；当前接口未发 HTTP-date 格式。拒绝/冲突慢速复核，不自动生成替代身份。
