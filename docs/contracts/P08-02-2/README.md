## 用户会经历什么

1. 开发侧生成一次专用主机升级包，在 4.23 原有部署上执行升级和发行绑定；只需必要的 Windows 系统授权。这个维护包与日后分发的母版、子版安装包分开。
2. 此后封包只选择母版/子版及功能。固定站点、信任和发行权限自动读取受保护的发行配置，不跟随开发者当前查看的数据源。
3. 普通用户安装：母版在 4.23 复用原主机，在其他电脑加入同一账本的同步节点；子版只登记桌面身份。都不选连接文件、不输业务密码。
4. 所有正式端只显示获授权业务功能；断线、登记未完成等技术状态进入有限日志，静默恢复。尚未完成的操作不显示成功。

**首次信任不可能从一个 IP 地址本身推导出来。** 本契约用经过部署所有者执行的专用升级包建立信任；这属于一次性主机升级，不是让每位使用者手工导入文件。旧 Host 尚无可重复发行授权、自动节点加入及服务端细分权限，因此只删除界面输入框不能完成目标。

## 决策摘要

| 项目 | 决定 |
| --- | --- |
| 固定业务入口 | `https://192.168.4.23:8477`；正常 TLS 校验加证书 SHA-256 固定校验 |
| 可信身份 | 主机确认的 `site_id + ledger_id`，加受信任 TLS 证书；IP 不是身份 |
| 正式版本 | `manager` / `sales`；Host 从已登记包读取角色与权限，不能使用客户端自报值 |
| 发行权限 | 开发电脑独享、可撤销、仅发行用途的凭据；不打入公共安装包 |
| 分发凭据 | 有期限、有额度、绑定包/站点/版本/权限的登记凭据；不能直接登录业务或管理 Host |
| 桌面身份 | 每个安装身份独立设备凭据、独立主体；保留凭据的重复安装复用身份 |
| 后台身份 | 母版另行登记节点；与桌面身份、销售主体和业务会话分离 |
| 写入与同步 | 只向 4.23 写入；从机异步同步，不自动接管，不要求共享部署目录 |
| A 的完成界限 | 契约与源码差距已明确；B 的源码及隔离检查已有独立交付；Figma 和安装集成源码见 C/D，F/G 及真实现场结果仍待后续 |
