# 发行授权与包清单

## 1. 协议版本

| 标识 | 本轮设计值 | 范围 |
| --- | --- | --- |
| issuance | `777-package-issuance-v1` | 发行主体、包登记与撤销 |
| enrollment | `777-auto-enrollment-v1` | 多设备登记、节点加入授权 |
| scoped_auth | `777-scoped-auth-v1` | 设备会话、能力与主体类型 |
| cluster_snapshot | `777-cluster-snapshot-v2` | 包含新授权模式的受控副本兼容 |

新接口位于 `/v1/automatic/`。路径中的 v1 是 HTTP 路由代号，不替代上述内容格式版本。旧 `777-device-auth-v1` 和邀请流程保留维护兼容，不能冒充支持新协议。客户端必须先在可信 TLS 通道确认全部所需协议；不支持时停止登记，内部记录 `PROTOCOL_UPGRADE_REQUIRED`，正式端不弹技术提示。不能回落为旧一次性票据或账号密码流程。

## 2. 发行主体

`issuer_id` 由一次性主机绑定创建，绑定 site_id/ledger_id、允许的版本、能力上限、节点登记权限、额度上限、状态和 epoch。发行会话只允许包创建、查询及关闭/撤销，不能读写订单、创建业务管理员或操纵现有节点。发行凭据也不能用于业务会话。默认可发行用户选择的母/子功能，实际权限上限以主机本地授权记录为准。

发行电脑不必登录业务账号；自动使用专用发行凭据取得最长 15 分钟的发行会话。普通包不携带此凭据。发行者撤销立即拒绝新发行；已发行包不隐式扩大或消失，维护方另有“连同所发包撤销”的显式操作。发行者失窃时应选择后一操作；审计必须记录受影响包数量。

## 3. 不可变包记录

`777-package-manifest-v1` 的公共字段与服务端记录一一比对：

| 字段 | 规则 |
| --- | --- |
| format、package_id、issuer_id | 精确格式及随机 UUID；同 ID 不得覆盖为不同内容 |
| site_id、ledger_id、trust_revision | 来自固定正式站点，不能来自开发者临时数据源 |
| delivery | `manager` 或 `sales`；分别映射业务角色 admin/sales，但 admin 不等于维护权限 |
| capabilities | 排序、无重复、仅目录中允许项；必选项和依赖闭包满足，sales 无 admin 项 |
| node_enrollment | manager 可为 true，sales 必须 false；不从业务 backup 等复选项推断 |
| release_version、artifact_sha256 | 版本文本及不可变发行负载摘要；不以版本字符串大小决定权限 |
| protocols | 精确的必需协议版本集合 |
| enroll_before、max_devices、max_nodes | Host 时间判定的截止时刻及整数额度；sales 的 max_nodes=0 |

默认登记期限 365 天、每包最多 256 个新桌面身份，母版最多 128 个节点；站点总量及发行者上限可进一步收紧，维护调整不出现在日常封包表单中。超过额度停止新增，已启用身份继续受原权限约束。ID 不回收计数，被撤销身份不释放名额，防止重复注册绕过额度。

摘要针对最终程序/脚本等不可变负载的规范文件清单（相对路径排序，逐文件 SHA-256），排除最终登记清单和凭据封套，避免“包摘要包含自己”的循环。现有打包完整性清单仍保留。Host 绑定该摘要与权限；这不是远程证明二进制未被修改，安全性必须来自 Host 权限执行。

发行准备分两段：构建负载并取得摘要 → Host 创建不可变包记录 → 把服务端返回的正式清单和随机登记秘密封入最终包。封包端先保护保存候选 package_id/秘密，再提交摘要；同 ID/秘密/内容重试返回同记录，内容或摘要变动须新 ID。Host 不保存或回传明文秘密，丢失候选秘密则关闭未交付包并创建新包。离线时不得用临时授权伪造正式完成。

拿到母版包即意味着得到该包所授的业务及节点安装权限，这是免账号分发的授权边界；该受限凭据不能访问主机维护接口，但可在额度内登记多台。不能宣称“包内没有任何凭据”或“仅隐藏 UI 就能防止改包提权”。

## 4. 生命周期

| 状态/动作 | 新登记 | 已登记身份 |
| --- | --- | --- |
| active 且期限/额度允许 | 允许 | 按现有权限 |
| 到期或 enrollment_closed | 禁止新增；原候选同绑定重试可取既有回执 | 继续，不因安装包到期停用业务 |
| package revoked | 禁止，包括凭据轮换/重新授权 | 相关设备和节点立即拒绝新请求，清会话、升纪元 |
| 单设备/节点 revoked | 原身份永不自动复活 | 拒绝请求；仍有效包不自动换新身份绕过本机撤销 |
| 新版本替换包 | 新 package_id、独立期限/额度 | 身份持有人及有效新包共同证明后原子切换权限，不做新旧权限并集 |

会话最长 15 分钟；每次请求复核包/设备/节点/主体 enabled 和 epoch，不能等会话自然过期才落实撤销。已提交业务不因撤销删除；已开始的有界响应可结束，不再授权新数据块或后续请求。

同角色升级保留设备 ID、subject、未决业务请求 ID，更新 package_id 与权限并使旧会话失效；只有持有原设备秘密且新包站点/账本一致才可转移。跨 manager/sales 不自动继承主体或历史归属，创建新的隔离身份，旧业务草稿及提交不跨主体重放。授权被撤销后不能通过普通升级解除撤销；需维护方明确恢复或重新分配。

节点包升级单独验证节点秘密与新母版包授权；桌面升级不顺带提升节点。任意节点只保有当前绑定包授予的复制权，不能使用设备会话替代节点凭据。
