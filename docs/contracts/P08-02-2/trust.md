# 固定站点与首次信任

## 1. 正式站点档案

`777-site-profile-v1` 严格字段如下；未知字段、缺字段和不支持的版本拒绝使用。

| 字段 | 类型和要求 |
| --- | --- |
| format | 固定 `777-site-profile-v1` |
| site_id | 随机 UUID；在已有主机配套升级时生成并持久化一次 |
| ledger_id | 已有账本 UUID，读取实际数据库；不得重新生成代替旧账本 |
| primary_url | 固定 `https://192.168.4.23:8477`，无用户信息、查询或片段 |
| tls | 当前受信证书 PEM 及其 DER SHA-256（64 位小写十六进制），二者必须一致 |
| trust_revision | 正整数，只允许经原可信通道批准的递增修订 |
| required_protocols | issuance、enrollment、scoped_auth、cluster_snapshot 的精确版本集合，见发行契约 |

档案不是秘密，可作为普通包的配置资源；真实性来自一次性绑定及已保护的发行配置。任何凭据仅在验证 TLS 与预期入口后发送，不跟随重定向。`site_id`、账本或证书不符均停止该连接，不因地址仍是 4.23 而接受。

## 2. 一次性主机升级及发行绑定

选择机制：**专用升级包预置临时信任锚，部署所有者在现有主机执行，开发侧自动回取正式档案。** 这个机制需要 B 实现，并非当前 Host 已支持的命令。

1. 开发侧“准备主机升级”自动创建 `upgrade_id`、临时 TLS 证书/密钥、256 位配对凭据及独立发行凭据。开发侧保护保存发行秘密与临时证书指纹；专用升级包携带临时监听所需材料、配对凭据摘要、发行凭据摘要及发行功能上限，不携带发行秘密。
2. 升级包是仅交给现有部署所有者的敏感维护产物，默认当天有效；不可混进母/子公共安装包、仓库或日志。由可信开发电脑交付、部署所有者执行这一行为是首次信任的来源。若升级包被他人复制或替换，不能声称仍具安全的首次绑定；撤销该升级编号并重新准备。
3. 4.23 本地提升权限后，自动按现有部署记录定位根目录，核对所有者 SID、机器、根目录及资源清单、主机角色、实际账本、现有服务证书。IP 只能筛选候选，不能授权覆盖。多个候选或不一致时不选任意一个，不初始化空账本；写维护日志并保留原部署。
4. 在保留原 HTTPS 8477 服务证书的前提下，临时开启专用于本次绑定的 `https://192.168.4.23:8478`。它使用第 1 步的临时证书，仅暴露绑定接口，拒绝业务、发行和节点操作。若端口占用，不夺取、不自动另选未知端口；记录可重试失败。
5. 开发侧用预存临时证书校验连接，发送配对凭据、`upgrade_id` 和随机挑战。主机校验摘要、有效期、一次绑定状态，返回挑战、正式站点档案和已登记的 `issuer_id`。有效窗口是升级包签发后 24 小时内、且本次监听启动后最多 30 分钟，重启不能延长。配对成功后仅同一绑定可幂等重读结果，不允许改绑其他发行者。
6. 开发侧先原子持久化正式档案及发行凭据，再通过档案固定的正常 8477 TLS 通道验证相同站点/账本并提交带挑战的绑定完成确认。主机收到有效发行确认后停止临时监听，清理本次临时私钥、配对摘要与自己创建的防火墙规则；保留无秘密的审计记录。超时也清理；磁盘/网络失败不提前标记完成。
7. 若开发侧已经保存档案但确认响应丢失，可经正常可信通道重试确认。若尚未取得可信档案就过期，只能重新准备维护绑定；不得转用忽略证书、匿名接口、共享业务管理员密码或自动信任首次见到的 8477 证书。

临时监听默认仅允许准备时记录的开发电脑地址访问，并保留凭据验证、限速及到期关闭。配对令牌只在固定的临时 TLS 通道发送；HTTP 请求体、URL、命令行均不得记录其值。升级包解包目录只允许部署所有者/管理员读取，完成后清理敏感材料。普通母/子安装器永不携带或调用这条绑定链路。

这是一次性准备依赖：没有完成可信绑定时开发端显示“主机配套升级尚未完成”，不产出声称可自动接入的正式包；不要求普通用户处理此状态。

## 3. 秘密边界与轮换

| 材料 | 保存位置与限制 |
| --- | --- |
| 正式 TLS 私钥 | 既有 Host 私有目录及运行身份 ACL；不发给发行电脑、客户端或同步节点 |
| 发行秘密 | 开发者 Windows 当前用户 DPAPI 保护存储，Host 仅保存摘要、权限上限和撤销纪元 |
| 包登记秘密 | 普通安装包携带；它是可分发的受限授权，不能假设不可提取；服务端期限、额度、撤销及权限为真正边界 |
| 桌面设备秘密 | 当前 Windows 用户 DPAPI 保护，持久化候选身份后才发登记请求；不在普通 JSON 中保存 |
| 节点秘密 | 由后台实际运行身份保护并限制 ACL；不能直接拿交互用户 DPAPI 密文交给另一服务账户 |
| 会话秘密 | 仅内存或必要的保护存储；有限期限；日志只记不可反推出秘密的关联 ID |

所有随机秘密至少 256 位，使用系统随机源；服务端摘要比较采用常量时间比较。不得恢复或输出用户先前给出的业务管理员密码。隐藏属性不是访问控制。

证书正常轮换由已验证的旧 TLS 通道下发下一证书及递增 `trust_revision`，主机记录有界重叠期，客户端先保存再启用；陌生证书不能自行证明自己。旧信任已丢失/过期且没有预置下一信任时，重新走部署所有者维护绑定及发行更新；正式端继续静默待恢复，不关闭 TLS 校验。本轮不实现自动故障接管，备用节点无权签发主机替换档案。
