# A：4.23 处理能力与 B 的交付门槛

具体值由 [limits.json](limits.json) 冻结为初始实现上限，不代表现场吞吐。调整必须同步协议样本与检查；容量不足只施加背压，不能丢弃唯一原件。这里的接收与处理都使用 4.23 本机磁盘，不访问 `共享\backup`。

## 有界接收和逐单处理

- 接收独立最多 4 个在途请求，每设备 1 个；与既有普通业务 8 许可分离，保留普通业务机会。每项 256 KiB、每批 32 项且总请求不超过 1 MiB；10 秒请求体超时。不同限制取更小值。
- SQLite 单写者为基线，接收事务和应用事务分别短小提交；不把多个合并工作线程误称为 SQLite 并行写入。单项应用预算 100 ms 为软调度目标，事务超时按 SQLite 明确结果核查，不在提交中途强杀写者。
- 每轮从最多 16 个不同订单各取 1 项；同订单必须等待正确前项。一个等待依赖、冲突或拒绝不占用全局工作槽，不阻止另一笔订单。全设备序号有缺口不等于所有后续订单必须停。
- 初始非终态接收上限：每设备 10,000 项，主机合计 100,000 项；离线原文总保留预算 2 GiB。原件、终态回执和碰撞证据均计入预算，防止大量冲突/拒绝或已应用原文绕过容量限制。超额不接收新的唯一操作，重复核查仍可进行；不能自动删除去重墓碑或未决原件来腾空间。
- 全局新请求初始 20 次/秒，单设备 2 次/秒，突发分别 8/2 次；按认证主体/设备计数，不按可自报设备字段或 IP。429 返回 Retry-After，客户端指数退避 1–30 秒、随机抖动；恢复连通时立即唤醒一次，不等固定长周期。正常未决回执查询间隔 2 秒，受相同背压约束。
- 缺失依赖最长等 24 小时后转人工保全；已知冲突前项的后继立即等待裁定。到期都保留原件，不自动作废业务单或在正式端弹窗。
- 4.23 磁盘余量低于 1 GiB 时暂停接收新原文及新离线能力签发，保留查询与恢复路径；真实写盘错误决定事务是否成功，余量预检不替代可靠提交。设备本机 D 也须有持久化失败路径。

## 备份与输出隔离

B 已将备份拆为准备一致快照 → 释放业务/授权门 → 本地编码 Excel/恢复文件 → 独立目标交付 → 短事务记录结果。共享路径打开/写入、等待网络恢复和重试在锁外；保持原快照及成功目的地不重写，见 [B 记录](../../verification/P08-02-3-B-intake.md)。

快照使用独立只读连接/SQLite 一致备份，固定 ledger 与队列边界；不能为避免锁而读取互不一致的多张表。长期只读快照要限时释放，防止 WAL 无限增长。普通业务、离线队列和输出各自有明确许可及取消点；关机先停止新接收，再完成或回滚在途本地事务，队列重启续做。

## B 必须交付的验证

| 检查 | 必须观察到的结果 |
| --- | --- |
| 迁移前有订单/客户/历史/回执 | ID、金额及归属一致；中断回滚或恢复到完整版本；未知库拒绝 |
| 同 ID 同内容 / 异内容 / stream 序号碰撞 | 前者只存一次，后者不改第一份；重启仍能区分 |
| 写原文前、提交前、提交后丢响应/崩溃 | 没有伪成功；原 ID 查询可核实；业务和去重状态无半提交 |
| 接收乱序、一个依赖缺失、另一订单到达 | 原件保留，正确等待，另一订单继续 |
| 设备/包/主体撤销、越权、错误账本、摘要篡改 | 分层拒绝，不能靠母版/开发版标志取得权限；无技术信息泄漏 |
| 超体积/批数/并发/积压，磁盘满与 busy | 有限内存和事务、明确可重试结果，原始操作不被删除 |
| 共享备份阻塞，Excel/复制同时运行 | 持续有本机接收/订单进展；测量接收/处理延迟与积压，不能只测端口可达 |
| 新恢复格式与新复制代 | 队列、回执及冲突候选完整；旧节点不误确认；本机未上传记录不被替换 |

在隔离数据测量并发接收、重连追赶与后台副作用同时运行时的延迟分位、吞吐、积压、CPU、内存和磁盘。4.23 硬件与真实数据规模未采集，不能把 CI runner 的结果换算成现场可带多少台。Windows 功能 CI 保留；仅安装包及其构建准备专项按用户要求跳过。提交后不轮询、不等待 CI，不用未读取结果签收 B。

## C 当前调度与资源边界

C 的实际调度比 A 初始“每轮 16 个不同订单”更保守：优先最多 4 个 received，逐项事务；没有 received 时按持久状态/UUID 游标扫最多 16 个 waiting_dependency。不按设备最高序号阻塞其他订单。前项应用/冲突/拒绝的同一事务最多唤醒 16 个直接等待后继，原文不变；新到达项不受旧 waiting 游标限制。工作进展后释放授权门并间隔 1 ms 继续，空闲/错误退避 100 ms，不对缺失依赖忙循环。极端持续收件下等待队列的全量重扫延迟及真实公平性仍需容量测量，不承诺 100 ms 是硬上限。

当前订单输入及详情超过 1 MiB 时自动处理转人工保全，先保存可核对的订单版本引用；拟应用模型超过 1 MiB 也不在自动队列重算。开发者快照读取每次 64 KiB；正式设备按版本拉取 lines/notes，每页 64 项、900000 字节，不放大响应上限。裁定原件及冲突引用计入既有 2 GiB 保留预算，容量不足返回背压并完整回滚。

100 ms 是初始软目标，未测得现场延迟承诺；保留字节核算仍有聚合 SQL，巨量数据下的扫描/恢复成本属于 F/G 的实测与优化范围。C 本地检查覆盖真实单项事务、乱序唤醒、冲突隔离、进程崩溃和独立 HTTPS 后台进展，不将其称为 4.23 压力验收。
