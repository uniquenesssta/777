# A：源码基线与现场边界

本节仅核对仓库 `2ca5cee`，没有访问 4.23、4.38 或用户共享目录。

| 边界 | 已有实现 | 新功能缺口 |
| --- | --- | --- |
| 本机数据库 | `quote-host/src/service.rs::load` 校验服务/账本/证书身份，`cluster/replica.rs::data_directory` 在主机使用 `private`，从机使用当前完整数据代 | 不可从共享目录里看不到部署文件夹推定 Host 不存在；不在主机未核实时创建空账本替代原数据 |
| 在线写入 | `quote-ledger/src/store.rs::mutate` 在 `BEGIN IMMEDIATE` 中提交订单、requests 回执、审计和账本版本；同 ID 异内容拒绝 | 没有异步持久收件队列；新订单内部 ID 由在线流程生成，需支持经验证的离线稳定 ID |
| 账本结构 | `store.rs::verify` 严格校验 schema 1/2 的结构哈希；当前写 schema 2，schema 1 有受控升级 | 不能直接添加表后继续冒充 schema 2；待受控升级 schema 3，并扩展完整性校验 |
| 设备与包权限 | 新设备会话 `automatic/sessions.rs::Context` 有设备 ID、主体和包清单；`automatic/business.rs` 与 `permissions.rs` 做能力检查/裁剪；旧设备会话在 `devices.rs` | 上传不能只取得 Actor 就放行，需取得设备上下文、发行状态和当前权限；发行/节点凭据不等于业务身份 |
| 当前未知回执 | 桌面 `client.rs` 的 `pending.bin` 绑定主体、URL 和证书指纹，查询原 request_id | 是在线操作核查记录，不是可继续编辑的离线订单库；只能保留原待核查操作，不能直接改成新订单重传 |
| 商品与历史 | schema 2 有 lines.line_id、order_versions、客户归集与修改差异 | 编辑来源仍含位置映射，需持久稳定商品项 ID 与本机操作依赖；不得把不同客户候选自动混合 |
| HTTPS 容量 | `host.rs` 当前 8 个业务许可、1 MiB 常规请求体、10 秒读请求期限；普通处理持有一个 `Mutex<Service>` | 新上传不可在读网络期间或整批业务执行期间长期占用该锁；不得称当前已具备并行合并能力 |
| 输出 | `host.rs` 先准备输出，再在锁外执行 `work.execute()` | 沿用快照与执行分离；不能在收件事务内导出 Excel/PNG |
| 每日备份 | 探测可在锁外进行，但 `host.rs` 调用 `backup::due` 仍持有服务锁；`daily_backup.rs` 含生成/交付 | **存在共享目标阻塞业务的剩余风险**，B 必须拆分快照和锁外交付，再验证接收不受共享断线影响 |
| 主从复制 | `cluster/snapshot.rs` 固定文件白名单、整代发布并严格核对 inventory；当前格式 v1/v2 | 必须协同识别 schema 3，不能把落后副本升为新主；终端本机未决库不能置于可替换数据代中 |
| 恢复 | `recovery.rs` 写 `777-data-backup-v2`，按固定表清单导出，不含认证秘密 | 当前恢复格式不含离线收件/冲突/去重状态，直接复用会丢未决操作或复原后重复入账 |

源码路径均相对 `crates/`，桌面路径相对 `desktop/src-tauri/src/`；历史文档的路径候选不等于本次现场证据。

现场升级前由既有维护渠道核对：有效服务根与账本 ID、服务身份/证书、后台任务、主从角色、数据量、磁盘余量、现有备份恢复结果。只读发现或维护采集即可，不向正式用户增加填写步骤。本次 A 不远程操作主机，也不把现场核对未完成算作软件协议尚未设计。
