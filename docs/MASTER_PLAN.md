## 1. 目标与边界

1. 在保留母版和子版核心报价能力的前提下，解决已确认的数据损坏、金额不一致及共享写入风险。
2. 形成与Tkinter无关的计算规则、价格版本、订单身份、失败状态和自动核对样本；这些是Rust迁移资产。
3. 让业务数据有可靠的唯一来源；Excel逐步成为兼容输入/导出报表，不再承载多客户端任意读改写账本。
4. 用Rust负责领域逻辑、存储和业务授权，Tauri负责桌面宿主，Web前端负责呈现与交互，不把Tkinter控件逐个机械翻译。

当前已按授权建立P02纯计算核心，两份原业务脚本已在P02-04接入，实机交互已按用户明确确认验收；后续范围按阶段授权执行。首期针对P01已登记的Windows桌面及现有局域网场景，不默认新增店铺分红、库存、税务、云同步、移动端或其他项目功能，不新增Linux/macOS产品验收。辅助环境的无界面核心证据不替代Windows实际交互与部署验收。

## 4. 通用验收与证据要求

- 每个Atomic Task记录实际基线/提交、改动范围、检查命令、真实结果、未执行项与恢复点；没有命令则明确采用人工操作步骤，不编造测试入口。
- 所有已知P1必须有关闭证据才可进入面向真实数据的上线。读写失败不可伪装为零；成功提交不可因视图刷新错误变成“未提交”；未知结果必须可查询并幂等重试。
- 金额UI、订单持久化、Excel、日/月汇总使用同一权威结果。黄金样本区分旧行为、已知缺陷、确认后的目标行为；正确性不采用模糊金额误差阈值。
- Windows本机：启动/退出、无管理员权限、中文路径、UNC/映射盘、不同DPI、多窗口/多实例；网络验证按对应阶段及用户批准范围记录。P03-01按用户确认验收通过，实测范围按原报告保存；保留读取/写入失败保护及合成故障检查，无额外补测待办。
- CI承载可复现的单元/合成格式/构建和隔离集成检查；当前已有分阶段Windows-only CI；P07 CI已覆盖实际Tauri窗口，后续增加两种正式交付类型的自动认证及安装产物验证。真实局域网和真实数据演练不能以CI替代。没有Linux/macOS产品门槛。
- 性能目标以P01登记的硬件/数据集/冷暖条件为基准。已按P01 performance-v1确认健康环境UI心跳p95≤100ms、最大间隔≤500ms；任务有明确取消/状态出口，实体断网/双机占用按用户既有决定不重新安排。达不到门槛先定位，不能事后改数掩盖失败。
- 绝对性能目标不针对不受控SMB系统调用作无依据保证；线程超时不等于底层I/O停止，不能对仍在写的任务直接重试。必要时在确认的任务边界使用可终止工作进程。
