## P08-01 新增：有序服务地址与正式母版隐藏配置

用户已给定顺序：优先 `192.168.4.23`，其次 `192.168.4.38`。按前文主备讨论理解为服务连接优先级，不改变普通备份的实际UNC目标。封包后的母版设置不显示4.23地址或允许编辑该地址；开发版保留部署管理能力。普通设置中若有包含4.23的连接/目录摘要，应使用业务名称或状态展示，不能通过同页其他文字又回显；实际路径与原备份操作权限保留。

**本次为需求登记，尚未实现。** 当前 `777-public-connection-v1` 只接受一个HTTPS origin及证书，原生会话/待核查请求也绑定单一服务身份；没有主备复制协议、自动接管或多地址封包。必须先补齐以下设计和实现，才能把该顺序用于实际切换，不得简单给两台独立账本配置相同订单接口后轮流写入：

1. 两个地址分别登记端口、可信证书、主机及共同业务账本身份；拒绝未知服务和证书不匹配的候选，保留稳定的操作员、设备与撤销状态。
2. 设计数据复制与保存成功的确认条件。用户尚未选择“两边持久化后确认”或“主机确认后异步复制”；此项待明确，暂不承诺故障自动切换后零数据损失。复制不是每日备份，不能拿昨日备份直接接单并称数据一致。
3. 保证任一时刻只有一个主机有写入权；切换前证明备用数据达到允许的接管位置并隔离旧主机。网络分区、主机重启或优先地址恢复时不能出现两个主机同时接单，也不能自动跳回落后的副本。
4. 提交结果不明时保留同一请求ID，在共同账本回执内核查；未核清前不换ID、不在另一台重新建单。同单版本冲突、历史快照、价格、客户归集、输出任务与权限须在接管后保持一致。
5. 扩展有序连接配置、封包输入、逐设备登记和原生传输。现有单地址格式兼容保留；新协议/兼容版本在实现时登记，不将下面旧格式表误当成新功能已经可用。普通母版设置不暴露4.23；开发配置可管理顺序和证书，日志继续限流且不记录凭证。
6. 新增功能先按既有Figma流程确定最小设置展示，再实现并验证优先顺序、故障/恢复、落后副本拒绝、未知提交去重、权限撤销及正式母版设置无4.23回显。沿用用户取消Windows母子构建准备验证的范围，不重新安排该验证。
