# P08-02-1 接入顺序与填写说明

适用于本轮新桌面源码；Windows 功能检查及现场业务闭环结果另见实现记录。23/38 的实际账本一致性仍需现场核对，不因两台已部署就视为已同步。

1. 在 23 Host 管理菜单查看状态与同步状态，确认主机运行；在 38 查看账本编号和角色，账本编号应一致，38 应为同步节点。不要把两份独立账本互相覆盖。
2. 在开发电脑运行 `npm run dev`。开发部署 → “导入或更换 Host 连接” → 选择 23 的 `Quote777Service\connection.json`，输入该 Host 的管理员账号与密码。来源文件只需复制公开的 connection.json，不需要共享业务目录或安装开发工具到 Host。
3. 查看在线连接与账本身份。开发者若要读取其他离线目录：选择该目录 → “读取此位置” → 填一个新的工作副本位置及来源管理员账号、密码。来源必须已停止服务；只在副本上编辑。读取 `.qbackup` 则用“导入备份”，同样选择新空目录。
4. 在右侧“正式封包目标”单独导入 23 的公开连接并验证管理员；核对地址、账本、版本、输出位置，再确认母版或子版。用户在本机执行封包，本轮没有代为构建安装包。以后临时读取其他数据，不会改此目标；重启开发端后需要重新核对封包目标。
5. 管理员给每台桌面电脑单独签发登记文件。安装对应母版/子版后，在首次界面“选择文件” → “登记并进入”。以后直接自动连接。Host 电脑不必安装桌面端。
6. 正式母版“存储与备份 → 业务数据保存位置”可填写希望使用的路径；保存后显示“已保存，暂未应用”。实际订单仍写入原 Host。报价表、图片保存位置的“发布保存位置”仍实际生效，与上面的偏好分别保存。

| 字段/文件 | 应填写或选择 |
| --- | --- |
| 在线 Host 连接 | Host 生成的公开 `connection.json`；服务地址是 HTTPS 地址，不是 D 盘目录 |
| 开发读取目录 | 可访问的兼容业务目录，或 `.qbackup` 恢复文件 |
| 工作副本位置 | 来源之外的新空目录；不会修改源目录 |
| 正式封包目标 | 单独验证的 23 连接；当前没有自动 23→38 切换 |
| 封包输出位置 | 开发电脑保存安装产物的目录 |
| 正式业务数据保存位置 | 当前电脑记住的目录偏好，暂不改变 Host |
| 桌面设备登记文件 | 管理员为该台电脑和发行角色单独签发的 JSON；不是 `.777join`，也不是公开连接文件 |

新部署默认 `Quote777Host`、`Quote777Service`、`Quote777Hidden` 同级；`Quote777Hidden` 为本机普通备份。固定隐藏备份是 `\\192.168.4.23\共享\backup`。23 已有部署保留已生效配置，本任务不更换其目录。

## 管理员签发与撤销

以下命令仅在已有开发环境的管理员电脑运行；服务电脑无需安装 SDK。`--subject` 填 Host 中**已存在**的账号名，必须符合所选母版/子版权限；没有对应账号时应先按现有账户管理流程创建，不能拿管理员账号发子版。密码在提示后输入，不写入命令、仓库或公共安装包。

```powershell
python tools/p07_provision_device.py --connection "D:\connection.json" --admin manager --subject manager --delivery manager --output "D:\母版-电脑1.json"
```

把示例 `manager` 换成现场已有管理员账号；子版改为 `--subject 实际销售账号 --delivery sales` 并使用不同输出文件。文件一小时内有效，每台电脑单独签发，不重复分发。旧文件内容不被覆盖。

```powershell
python tools/p07_provision_device.py --connection "D:\connection.json" --admin manager --list-devices
python tools/p07_provision_device.py --connection "D:\connection.json" --admin manager --revoke 实际设备UUID
```

撤销只作用于指定设备。重新登记时签发新文件，在该电脑导入；原草稿和未决业务请求不删除。若有未决请求，只能恢复原服务、原业务账号后核查。不要复制另一台电脑的 profile 或设备密钥。

旧版 38 节点无法通过现有接口单独核对账本身份，所以本轮封包目标先使用 23；如需改成旧 38，先处理协议兼容缺口，不能只替换地址。真实上线前仍要完成一笔测试订单、修改差异、Excel/财务导出、双位置备份、独立恢复和 38 同步核对。
