# 本机数据切回与导航稳定性（2026-10-20）

## 最新需求优先

连接状态不能决定上方已允许页面是否存在。开发者的本机数据入口及封包独立于 4.23；正式端导航仍按封包权限，不显示技术连接提示或登录退出。此前“未建立会话就显示空白工作区”的界面验收标准不再适用，测试同步改为“保留允许导航、保持静默、没有数据身份时不能冒充保存成功”。

## 原因与修改

- 原 App.tsx 以 session 是否存在控制整个业务导航和工作区；会话建立失败会只剩开发者工具。本次从版本/权限计算展示角色，导航与会话解绑；认证和实际写入仍由原生层执行。订单及设置页面角色标题也保持稳定。
- 原连接表单修改 URL 不会一起替换证书，通用连接会使用在线 Host 的默认/缓存身份。截图中的地址变化不足以单独证明证书错误，但这种操作无法可靠恢复启动器的本机身份。
- 既有连接弹窗增加“切回本机开发数据”：通过独立 localDevelopment.ts 向本机启动器读取 status，再 select 当前 root，initialize=false；不传入远程证书，不新建空账本，不重置目录。原生层保留未确定回执保护，按原有 local 模式恢复本机身份；重载后读取正确账本。
- 开发者启动器可用时主动启动本机/已选数据源的既有 bootstrap，不依赖是否有历史 bootstrap 文件来决定是否尝试恢复。
- 后台重连不再把当前页面强制切回报价；连接丢失不再用 connected=false 全局锁住已有有效本地会话。没有可用业务会话时仍禁用业务提交，保留导航与开发工具。
- 真正的请求忙碌与没有业务会话分开，避免无会话时永久显示“处理中”或“正在读取”。
- 开发者切回本机是切回原工作账本，不把远程账本的订单自动混入本机开发账本。正式版本地入账、持久续传继续沿用已初始化的原生本地数据库流程。

- 静态：TypeScript 检查、git diff --check 通过。
- 前端构建：Vite 构建通过；Radix use-client 提示仍是非失败警告。
- 单元测试：57 项通过，包括新增导航权限测试。
- 浏览器自动测试：45 个不同用例通过（34 个已有连接/展示回归、4 个新增源恢复与无会话导航回归、7 个封包独立性/真实业务回归）。部分用例采用明示的 UI bridge stand-in，只证明界面行为；其中 6 个业务用例使用真实 Rust/HTTPS fixture。

- 真实开发者恢复链：启动两个独立 TLS 测试账本，从本机切到另一 Host，停止后者并确认 bootstrap 失败；按新增按钮相同的 status/select 调用恢复本机。核对本机账本 ID、完整连接证书、原有订单及目录均保持。检查加入 p07_developer_check.py 的常规流程；可用 --source-recovery-only 单独执行。
- 真实正式端离线链：停止 Rust HTTPS Host 后，本地保存订单/备注；关闭重开客户端，恢复同一保存回执、修改同一订单；客户端关闭时独立后台进程上传到重启后的 Host；中央仅一笔订单，最终金额 3000 分，确认投影及历史缓存已回传。9 项检查全部通过。

## 更新后操作

开发电脑 git pull 后重新启动 npm run dev。进入开发者工具 → 开发数据 → 选择或更换后台连接 → 切回本机开发数据，无需手填本机地址、证书或账号。已选远程数据源不会被启动过程擅自改成本机；必须由用户明确切回。
