## 识别和写入边界

[schema.py](../../quote_files/schema.py)是26个业务字段、行类型和身份字段的唯一列定义。两端导出、读取、样式和订单操作按字段映射，不依赖金融列或订单ID的固定位置。

| 识别结果 | 读取 | 追加或编辑 |
| --- | --- | --- |
| identified-v1：26列、行类型、完整5列身份 | 校验UUID、版本、状态、原始请求回执、每单总计与明细 | 格式和金额完整时允许；编辑仍需稳定订单身份及旧页面哈希 |
| tagged-v1：26列及明确行类型，无身份 | 读取明确类型；没有身份的历史记录不补造ID | 允许保留历史行并追加新单；历史行自身不可编辑 |
| legacy-26：旧26列，含`用户`别名 | 有效明细/明确总计可只读核算，历史订单歧义提示 | 非空旧文件拒写；没有数据且完整的已知模板可追加新单 |
| 上述字段重排，或旧`高度`/`宽度`别名 | 使用规范字段映射，schema标注`-mapped` | 仅符合其余写入条件的布局可写；不重置原表头/旧金额/旧身份 |
| 额外`备注`列 | 文件说明可读，未确认归属的旧备注不当作订单备注 | 明确类型/身份及其余条件完整时允许 |
| 缺少任一26列、重复表头/别名冲突、未知列、身份残缺 | unsupported，金额为空；母版可浏览原表 | 拒写原件 |
| 未知附表、未支持附表格式、图形/宏/外链/自定义XML等扩展、非第6行表头 | 已知明细可读时标注只读 | 拒写，不通过保存丢弃未知内容 |

新模板只可建立在空工作表；存在数据时明确拒绝，删除了原先无条件清空模板的路径。写入前、变更后分别校验，变更后身份/回执/金额不一致不发布。金融和原文字段的样式按列名设置；新客户、订单号、微信、原始表达式、备注及附表字符串强制为文本，`=1+1`不会被写成公式，前导零保留。

读取和工作表枚举共用有容量限制的文件入口：源文件20MiB，ZIP最多2048条目、展开64MiB，明细最多100000行/64列，表头扫描前40行；不支持的容量明确返回失败/不支持。本轮不新增生产依赖。

## 金额与状态

[reading.py](../../quote_files/reading.py)返回`LedgerRead`：`status=ok/error/unsupported`、整数分`totals`或null、schema、issue代码/原因/位置、可见明细、分组、源SHA和摘要来源。失败不是正常零单；过渡数字访问遇到失败抛错。

- 摘要仅在表头之前按`总收入/总成本/总利润`标签查找；明细表头的`总成本`不污染摘要。摘要缺失按有效明细精确十进制求和，排除总计和作废；摘要存在时校验完整性及与明细的一致性。真实零摘要仍是存在，不能据零值猜测缺失。摘要不完整/不一致、非法/非有限金额、收入成本利润不符明确失败。
- 公式不执行。无可读缓存报`FORMULA_WITHOUT_CACHE`；有缓存仍核对行/单/摘要金额，并标注`FORMULA_CACHE_USED`及缓存时效未验证。含公式文件只读，不能保存覆盖公式；一致缓存不证明已重新计算。P01合成缓存2但成本4/利润6的例子明确失败，保留历史材料。
- 文件列表显示读取状态和原因，失败金额/行数显示`—`；合法零文件计入文件数。全部统算只累计成功文件的整数分，失败/不支持数量和“部分”状态显性显示；全部读取失败时金额显示`—`，空目录正常显示零。重复文件不会因字节相同自动去重，因为同字节不证明同一业务来源。

## 历史分组

新单按稳定订单ID分组，核对订单总计，作废不计有效金额。旧记录候选含客户、记录时间、订单号和微信；明确且金额一致的导出总计边界才形成历史导出块。同秒同客户但订单号不同不会合并；同前缀多明细而无稳定编号/明确边界报`AMBIGUOUS_LEGACY_GROUP`，行和文件总额保留，子版“总销售额”显示`—（历史归属待核对）`。无可核对归属的总计单独提示，不作为订单金额重复累计；只有总计而无明细报错。

此处没有给旧单分配持久ID，没有自动转换或写出历史迁移副本。实际旧文件转换需按P05/P08的副本、归属确认、对账和审计流程；备注浏览/作废恢复界面仍由P03-04完成。销售成本保密与身份认证仍由P05/P07完成，隐藏字段不是权限隔离。
