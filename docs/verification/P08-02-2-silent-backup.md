# P08-02-2：备份未完成时静默与恢复补写

2026-10-19（Asia/Shanghai），基线 `d015d31b374018f0e2578b086ceae3d3884b6003`，分支 `stage/p08-cutover`。用户要求不显示“部分交付”，局域网恢复后后台自动继续，并询问主服务是否需持续运行。

## 实现

- `backupPresentation.ts` 对未完整、失败、未确认和无备份结果返回空文案；设置页隐藏整行状态及最近成功时间。备份操作未取得完整回执时也不显示结果反馈，刷新失败不会拼接提示。仅确认完整成功后可显示原正常业务状态。授权范围保持。
- 独立 `daily_backup/schedule.rs` 负责每日调度、短周期探测和历史补写。Host 调度由 15 秒缩短为约 2 秒。预检先在业务锁中读取本地状态，再释放锁探测尚未成功位置的标记文件；标记可访问不等于身份可信，实际交付仍验证目的地身份和文件摘要。
- 等待时不生成 Excel、不读取/复制整份快照、不写失败进度或逐次记录探测日志。目的地恢复后重新运行交付，跳过原快照已经成功的目的地。已成功普通位置随后暂时离线，不阻止隐藏位置补齐。
- 待补写状态及不可变 qbackup/xlsx 保存在原数据目录；服务重新读取状态继续，沿用同一 snapshot_id 和字节内容。每日时区、按日去重、缺失历史日期不伪造及原恢复格式保持。
- 正式母/子版和随附后台不产生问题日志的要求保持。开发/独立维护日志原有限量规则保持。
- Figma 文件 `2ek9bkIz5ldyhjZnnvIuNu`、页面 `21:2`、720px 局部 `120:2314` 隐藏状态节点 `120:2320`，自动收高至 220px；复用现有 Field/Button。已检查 Figma 及 1440/720 浏览器局部截图。

## 主后台与数据汇总

4.23 主 Host 后台持续运行、开机恢复，接收各桌面的请求并统一落账；母版其他电脑的后台接收同账本副本。关闭桌面窗口不停止后台。订单请求保留原请求 ID 去重，同一订单的并发修改受版本校验保护；没有新增多主写入、离线正式落账或自动合并程序。主机不可达时草稿/未知请求保留，不虚报保存；网络恢复后后台的副本同步与备份补写各自继续。

“恢复后立即”在这里指下一次约 2 秒探测发现备份目的地可访问即开始补写，不等第二天或要求点击按钮。Windows SMB 调用、身份/权限校验和实际文件传输会增加耗时，不承诺 2 秒内完成；网卡连上也不等于共享目录已可访问。
