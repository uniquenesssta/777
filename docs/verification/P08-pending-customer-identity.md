# 原生请求锁定与客户识别纠正（2026-10-20）

## 根因与修复

用户 Windows 截图和 runtime(8).jsonl 显示：DeleteOutput 在本机以 PACKAGE_PERMISSION_DENIED 拒绝，随后出现 PENDING_REQUEST_REQUIRES_QUERY；Host 的订单、价格、设置读取仍成功。上一提交 9be376a 遗漏了 pending 路由对 /delete 的许可，且在这次校验前已经写入 pending.bin，导致未发送的删除请求阻塞后续变更。这是实现遗漏，先前 UI 模拟和独立 Host 测试没有覆盖完整原生调用。

现在 retry/delete 共用严格的 UUID 路由解析，仍保留 exports、finance 和服务端权限校验；新请求在写入本机待处理记录前验证路由、身份和导出范围。恢复旧请求保留原 subject、地址、证书和 request_id，先核查回执，再按原编号重试。未知结果继续保留；明确拒绝可清理该待处理请求。前端遇错后读取本机实际 pending 状态，避免原生已解除而界面仍锁定。

更新后旧版遗留的删除请求可通过“按原请求重试”恢复。不会手动删 pending.bin，不会批量抹除订单、回执或离线队列。正式端没有新增技术提示或日志入口。

## 客户识别

- 报价自动匹配发送结构化 identity，仅包含客户／淘宝 ID 和微信号；去除首尾空白后，同字段完整相等。不是子串匹配，也不跨字段匹配。
- 淘宝 ID 或微信号任一匹配即给候选；两项指向不同客户时保留各组供选择，不自动合并。
- 只填订单号不查客户、不出现客户选择；已有客户候选显示“是否是这个客户”，保留新建该客户订单或继续编辑原订单的选择。提交因需要客户确认而被拒绝时，有实际匹配才打开选择弹窗。
- 更改淘宝 ID／微信号清除此前客户选择；仅改订单号保留选择。
- Host 在分页前按身份过滤；本机离线查询采用相同身份规则。订单记录的普通查询仍支持订单号。已有账本保存及离线上传客户判断本就仅使用客户／微信，未引入订单号身份关联。
- Host 新增可选 identity 查询字段，旧的普通查询继续兼容；新桌面连接现场服务需同步升级 Host，不能用旧的模糊搜索冒充身份匹配。
