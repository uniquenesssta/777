# 本机封包与服务端自动识别修订

基线：`ec78976a8a26390d786f3e571786b2a42f7ad742`；分支 `stage/p08-cutover`。用户 2026-10-20 明确：开发者本机选择母版/子版及权限封包，不应先向 4.23 认证；本次“对啊，开始修改”授权实施。P08-02-3 E 暂停。

## 已修改

- 本机 Ed25519 签发身份自动初始化并受 Windows 账户保护。封包控制器与 Node 发行流程不调用服务器发行会话、配对或建包接口，不依赖当前开发业务数据源。候选秘密先持久化，失败重试复用原包。
- 新签名包绑定角色、权限、资源摘要、版本、包编号、登记期限/额度、公开首次接入证书和登记秘密摘要。每个新包限 1 个桌面身份，母版另限 1 个后台节点；沿用身份的重试和升级不重新创建用户。
- 普通 Host 出包携带与本机签发身份配套的接入公钥及接入服务 TLS 材料；4.23 的 `deploy.cmd` 自动执行所有者校验、正常停止、兼容更新、独立入口防火墙配置并重启，不要求开发电脑回连确认。保持原 8477 证书、账本、账户、任务所有者和备份位置。
- 专用固定证书 HTTPS 入口负责验签、幂等登记、额度和撤销检查，返回真实业务绑定。端侧保存受保护绑定缓存；重新打开可以恢复原设备及未决请求，不把另一账本或另一包的响应混入。
- 初次离线安装母版时，任务使用真实签发者标识，账本/站点留空；后台接入并核对完整副本后才补入实际身份。已有主服务复用，新的后台任务继续静默等待联网。子版不带后台资源。
- 开发者“封包授权”页面从现行导航移除，Figma 同步修改；只保留“应用封包/开发数据”。正式端权限、静默接入和禁用诊断日志边界保持。
- 旧在线发行接口、旧包和关闭补偿队列保留兼容；新本机候选不送进旧远程关闭队列。已经分发且登记的包仍由服务器维护撤销，取消本机任务不伪称远程撤销完成。

## 现场边界与使用方式

开发电脑 `git pull` 后使用 `npm run dev`，进入“开发者工具 → 应用封包”。4.23 不在线不再阻挡本机签发。现有服务器需在同一开发电脑重新生成 `npm run package:host` 的普通 Host 包并更新一次，才能识别新签名包；无须每次封包认证服务器、复制 Quote777 数据目录或填写业务密码。

Host 部署包含接入服务私钥，只交给后台维护者；开发签发私钥不离开开发电脑，普通母子安装包均不包含这两类私钥。共享 `backup` 仍只是备份目的地。

本次没有构建最终母子安装包、没有运行构建准备专项、没有执行 4.23/4.38 升级或 Windows UAC/任务/防火墙现场操作。PowerShell 5.1 和 DPAPI/任务跨账户行为仍由对应 Windows 检查与现场实际运行确认。提交后正常触发 CI，不轮询，不声称 CI 已通过。
