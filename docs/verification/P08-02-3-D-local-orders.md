## 保存与恢复

正式母版、子版在首次真实登记、Host 显式 apply、签名租约与公开价格校验成功后，沿用现有订单操作在本机保存正式单。本机订单、不可变上传原件、本地修改前后值及保存回执在同一个 SQLite WAL/FULL 事务中提交；失败回滚且保留输入。保存不依赖 React 页面定时器或服务器响应。

窗口保存前先持久化稳定 save ID 和原始输入；原生提交后窗口丢响应或关闭，重新打开按原 ID 读保存回执，关联原订单，不再新建。原 ID 异正文拒绝；订单、商品行、备注、设备 stream 和操作身份稳定。编辑保留历史价格，原生核心重算金额，主机仍独立重验。备注、作废/恢复及客户归集沿用原权限和版本检查；当前客户自己的订单不形成自依赖。

本机库位于当前 Windows 用户的 `%LOCALAPPDATA%\cn.uniqueness.quote777\manager|sales\offline.sqlite3`，独立于 Host Service、主从完整副本和安装目录。订单内容、价格、原件、回执和缓存块均通过 Windows DPAPI 保护；索引仅保留标识、计数和状态。签名租约绑定站点/账本/设备/主体/包/能力及公开价格摘要，本机配置和包也必须匹配。不能复制别人的配置或修改版本标记取得权限。

独立受保护的时间/序号高水位在数据库写保留期间 fsync 并替换；旧 SQLite 副本不能复用已分配序号。允许失败后的序号空洞。租约到期或时钟回拨阻止新写入，保留已有记录；已获知撤销后停止本地访问和上传，不删除原件。断网期间无法实时知道远端撤销。受控换机、旧库/高水位整体恢复及 stream 重绑仍属 F；本轮不提供恢复导入入口。

## 独立后台与确认结果

正式 Windows 安装运行入口在首次有效业务登记后为当前用户注册 Run 项，启动同一已安装程序的 `--background-sync`；无控制台、WebView、开发环境或账号输入。关闭业务窗口后独立进程继续；下次用户登录后恢复。用 OS SQLite 锁保证同一配置单 worker，进程崩溃释放锁；上传锁独立于业务写库，网络等待不锁住本机保存。包更新使旧 worker 退出，新程序接管。卸载不主动删除用户业务数据。

worker 每两秒调度，有限 TCP 探测只在连接恢复时解除瞬时网络退避；实际业务始终重新通过证书指纹及 HTTPS 认证。429、授权失败与其他背压不被探测绕过。自动会话续期、真实签名租约/价格更新、原在线 pending 核查、有限上传、回执查询、确认 feed 与完整订单/历史分块均在原生端执行。

收到 202 仅标记可靠接收；原操作及摘要不删。applied 或明确裁定后才更新确认状态。一个冲突链不阻塞无关订单；回执查询优先新接收项，并用持久游标轮询未决项。主机确认投影先进入 confirmed 区，存在未决修改时保护 working 区；明确归并才建立目标映射，不擅自换单重放。

新增 Host `/v1/offline/ready` 明确本机模式、恢复/授权 epoch 和价格版本；旧 Host 或 receive_only 不开启 D，继续既有在线路径。订单分块增加既有业务修改摘要；差异使用有界 diff-chunk，完整摘要核对成功后才发布，不显示半份差异。销售缓存仅有本人获准数据，无成本利润；权限收窄清除旧私密投影及碎片。原操作只含业务原始输入，不含推导的成本利润。

查询、搜索、客户多单、详情及既有修改记录读取授权本机投影；Unicode 搜索与 Host 共用原冻结规则。历史订单在后台逐步缓存，尚未下载的记录不能承诺断网可见。版本改变的分页静默重读。报价输出只用无未决改动的确认版本；中央报表仍只统计 Host 已生效记录。本机公开金额计算不伪造成本或利润。
