# P07-06 每日双格式数据契约

适用：原生 Rust 主机与开发者版；格式 `777-data-backup-v1`。本文件补充当前阶段任务书，不是平行任务书。旧备份只保留读取兼容，停止新建完整服务包；不清理既有用户备份。

## 文件与运行规则

每个快照发布一个目录：`账本UUID-北京时间日期-快照UUID`，仅含 `data.qbackup`、`data.xlsx`。普通和隐藏目标使用同一缓存生成的逐字节相同文件。目标先写临时目录、逐文件校验，再原子改名；已存在且内容不一致时拒绝覆盖。目录内没有程序、字体、WebView2、TLS私钥或密码数据库。

每天默认北京时间23:00执行，开发者可以设置0–23整点；不使用电脑所在地时区。无业务变化仍备份。服务每15秒检查一次；当天已过设定时间且尚无快照时补做当天，不伪造停机错过的历史日。手动“生成今日备份”会提前固定当天完整快照；再次点击只核对/补写原快照，不更新为当天稍后的数据。保存路径本身不生成快照。用户尚未指定历史保留期，两个目标中的历史文件均不自动删除。

当天生成中断且未发布缓存时，可以重新捕获；完整缓存形成后，双格式、双目标重试均复用该缓存。过去日期只重试真实已生成但投递失败的缓存，不以今天数据补造旧日期。仅已投递完成的往日内部缓存会清除；目标里的每日文件不动。内部状态文件保留日期、快照身份及两处结果。

普通位置失败不能阻止隐藏位置投递，反之亦然。母端只看到普通结果；隐藏位置错误仅开发者状态可见。隐藏位置未配置时，不把普通成功说成隐藏成功，也不反复生成当天数据。目标改变后，当天缓存可补写新目标，旧目标保留。

## 软件恢复数据

`.qbackup` 是UTF-8 JSON，根字段为 `format`、`sha256`、`data`。SHA-256是Rust v1类型按声明顺序序列化 `data` 后的摘要；映射键使用BTreeMap字典序，数组保持顺序。每个逻辑表记录明确列序及完整行值；整数保持JSON整数，空值保持null。附件以base64保存。文件最大256 MiB，超限明确失败，不截断。

数据范围：

| 分组 | 表/内容 | 规则 |
| --- | --- | --- |
| 账本 | ledger_meta、price_versions、requests、orders、lines、notes、import_batches、audit_events | 所有业务列及全部记录，含原始JSON、冻结成交价格、金额整数、状态历史与原始操作回执 |
| 主体 | users的id、username、role、enabled | 保留历史人名和关联编号；不带salt、verifier、密码、令牌 |
| 输出 | jobs、receipts、events | 保留冻结输出请求、记录、校验与关联；恢复时queued/running变为failed并清除目标写入路径，须用户明确重试 |
| 附件 | 输出索引验证引用的全部output-blobs/*.xlsx、*.png | 不依赖原电脑路径；校验原始字节及全部引用。外部发布路径仅供参考 |
| 元数据 | 格式/源版本、快照UUID、UTC生成时刻、北京时间业务日期、账本inventory | 恢复先核对结构、引用及完整账本摘要 |

暂不包含未提交草稿、尚未导入的外部文件、软件安装程序、原电脑偏好目录或登录环境。已导入源文件的原始base64及字节数位于import_batches.mapping_json，随完整账本保留；不重复另存同一原件。主机输出原件全部纳入，不以“可重新生成”为理由省略。

恢复到新的主机目录及独立备份目录，禁止覆盖既有目录。先验证账本，再初始化新运行环境、插入全部逻辑记录、核对inventory和附件关联，最后允许软件切换。运行程序来自当前安装/源码构建，不来自备份。当前源账本继续保持，失败不切换。恢复账号由本机开发者控制器创建并保存；历史人员均禁用且旧密码不可用，设备授权、登录会话及授权票据不恢复。恢复当天同日期备份会复用原快照，避免隐藏位置重复冲突。

v1导入使用固定表和列允许清单，拒绝未知字段/表、未知版本、摘要不符和业务校验失败；不执行备份内的SQL或路径命令。未来schema升级必须保留v1适配及历史样本回归，不能仅重命名版本号。当前实现不声称所有历史程序可导入未来格式。

## Excel字段映射与独立阅读

工作表：`账本_表名`、`输出_表名`、`人员`；所有列按同快照逻辑表原列顺序输出。`字段字典`逐列给出稳定字段标识、中文名称、单位/解释；`说明`给出账本与快照身份、行数、时区和关联规则。

- 客户、单号、联系方式：orders.details_json，展开到`结构字段`；商品/价格版本及项目：price_versions.payload_json。
- 原始数量/折扣：orders.input_json、lines.raw_json、normalized_json；成交价格：lines.price_json。金额`*_cents`单位为分，完整整数文本。
- 备注：notes；作废/恢复历史：audit_events；每次业务操作的原始回执：requests；历史导入映射及报告：import_batches。
- 关联：price_id连接价格表；order_id连接订单；owner_id/actor_id/author_id/published_by连接人员.id；request_id连接请求。结构字段采用JSON Pointer路径，嵌套对象和数组逐值展开，并标注客户/商品/数量、高宽（米）、单价（元）、倍率、折扣及计价方式等中文字段说明。
- 所有单元格是文本，前导零和长整数不经浮点转换；用户文本不成为公式；无宏、外部链接或外部数据查询。
- NULL显示`〈空值〉`，空字符串显示空白，零显示`0`；原始类型和值由.qbackup无歧义保存。订单active/void分别表示有效/作废。
- 超过30000个UTF-16单元的字符串，按最多12000个Unicode字符分段写入`长文本`，记录工作表、原始数据行、字段及分段号；连接分段可还原原值。结构展开中的长值同样处理。
- 每张表最多999999条数据，超限分表并重复表头；行号仍按原逻辑表连续计数。没有静默截断规则。
- `附件关联`列出.qbackup内原件，Excel不嵌入程序或附件二进制。

自动验收使用Rust calamine和Python openpyxl独立读取，不把它们冒充实际Microsoft Excel/WPS视觉验收。目标电脑Excel/WPS打开与用户视觉确认仍需登记版本及结果。

## 设置与权限

开发部署页设置普通位置、隐藏位置及每天整点。隐藏目录须为空目录或已有777隐藏数据标记，且与账本、普通备份位置互不包含。Windows应用隐藏/系统属性及现有私有ACL；不承诺对系统管理员不可见。配置只保存在主机private/daily-backup.json，不进入公开连接配置或封包连接材料。

开发者本机控制器通过已有管理员身份在停止主机后设置；正式母子版不编译开发者能力，服务API拒绝修改备份计划。子版无备份读取权限。恢复后继承当前开发者预设的隐藏位置及每日时刻；新的普通备份位置随恢复目录建立。没有远程后门、第三方上传或备份历史管理页面。
