# 报价会话、订单切换及清理（2026-10-20）

## 实际行为

- 报价只保留本次运行内容。原生 Desktop 每次创建独立 runtime_id，前端按此标识管理 sessionStorage；同一次运行切页或重载保留，重开软件即清空。升级时移除旧 localStorage 中的普通、按来源和受限草稿，不动其他偏好。原生待确认回执、正式订单及离线同步队列不受影响。
- “一键清除”清空当前客户、订单号、微信、商品、折扣、核价及编辑关联；已保存订单保留。正在提交或有待核查请求时暂不可清除，以原请求回执为准。修复核查已保存后残留的“提交未完成”弹窗。
- 订单切换原来卸载客户页并重新请求，已提交的查询还额外等待 250ms。现在两种视图保留各自查询、分页、加载数据，切换不重复请求；用户发起的客户查询立即执行，报价输入自动匹配仍保留 250ms 防抖。首次读取仍取决于 Host 响应。补齐新容器的高度布局，防止客户表格被压缩。
- 开发者“清除所有封包”先显示可清理目录，再确认删除。跟踪本启动器生成的输出目录，兼容现存任务、签发暂存和已知输出位置的 release.json；删除对应安装包、失败残留和逐包资源，保留源代码、编译缓存、本机签发身份、已安装程序和业务数据。运行中的构建拒绝清理；删除前检查所有目标，拒绝链接/reparse point 和包含已知业务配置/数据库的目录。用户另行搬到未知位置的历史副本不会全盘搜删。注册失败不把内存任务误置为运行中。
- 导出记录仅失败项显示“删除记录”。新接口 `POST /v1/outputs/{id}/delete` 校验权限和状态，追加删除事件与幂等回执，列表持久过滤；不抹除原始审计/回执，不删除订单和导出文件。已完成或执行中的任务不能删除，删除后的失败任务不可重试；删除末页最后一项返回上一页。
