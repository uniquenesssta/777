## 操作方式

- 在仓库根目录执行 `npm run dev`（desktop目录也支持）。
- 报价工作台填写客户/淘宝ID、微信号或订单号，匹配候选后选择“该客户新建订单”，可用不同订单号保存到同一客户；选择某笔订单“继续编辑”才更新原单。订单记录可在全部订单与客户归集之间切换，展开客户查看独立订单及有效金额合计。
- 订单详情“继续编辑”：保留原记录身份及备注；调整商品、数量、折扣后计算并保存。详情可看保存前的版本/金额摘要。修改期间发现版本冲突则保留草稿，重新读取后处理，不能静默覆盖。
- 母版“导出记录”选择日期范围，生成内部财务Excel；单笔财务导出仍在详情。成功记录显示“打开文件夹”。日期范围按北京时间原订单日期筛选，导出全范围而非仅当前列表100条。
- 问题复现后提供根目录 `logs` 内本次启动的整个文件夹即可，通常只有 `runtime.jsonl` 和一个小型锁文件。无需寻找development/desktop/host/ledger四份文件。

## 已落实的数据规则

账本schema由1原子迁移至2，新增customers、order_versions及订单客户/明细价格快照引用；未知schema拒绝、不尝试修补。原客户/订单信息保留，历史记录不按名字批量合并。客户选择明确记录稳定ID；旧订单作为归集锚点时不暗改其金额和修订。新建同一客户的非空订单号不可重复，不施加全账本唯一限制；模糊搜索仅用于候选。标识冲突拒绝，用户可明确重新选择关联或作为新客户，不能悄悄归并不同主体。

编辑在单次事务内验证原版本、行来源和权限，存档修改前完整快照、关联审计事件，再替换当前行并递增版本。未换商品的原行用原成交价格版本，新行及换商品用当前价格；折扣按现有顺序规则重算。请求ID去重，超时查询回执不会重复追加。当前订单及客户汇总只计当前有效版本。销售仅看到/编辑本人订单，不获得他人订单或成本利润。

`.qbackup`逻辑备份升级v2，保存客户和修改前版本；v1可验证并导入，旧完整恢复包/原始导出仍使用其冻结内容和格式。已有每日快照不改写：当天已生成旧阅读格式时，重复备份仍补写同一冻结快照；下一日快照使用新格式。需要立即阅读新格式可直接导出期间报表。原备份文件、ACL及Hidden/System属性不被清理。

## Excel与输出位置

第一个工作表为“阅读说明”，随后自然月工作表，月内按日、订单、明细排序；有历史时另含“订单修改记录”摘要。每日备份还保留完整辅助表，报表不冒充完整恢复数据。北京时间跨月边界、负利润、作废排除、前导零、长编号及输入公式转普通文本均有回归。

21个中文业务列含客户/微信/订单号、商品、计价方式/尺寸/数量、销售单价、顺序折扣、明细金额、订单收入/成本/利润、状态/备注/内部标识/K及最后修改时间。金额为精确元文本，日/月合计只计一次有效订单；汇总展示行不能与订单合计再次相加。冻结首行及四个标识列，支持筛选和横向阅读。较长备注分续行保留。范围报表保留生成时间、账本版本和日期范围元数据，之后编辑不改写已生成文件。

内部财务文件实际位于服务私有 `output-blobs`，普通报价输出沿用所选输出位置。文件夹入口先经服务鉴权获取该条已完成记录的真实路径，再由原生固定能力打开父目录；不拼接shell命令。远程服务的本地盘路径不能误当成本机路径打开，会明确提示在服务主机访问；客户端可达UNC可打开。权限不足、无产物、目录不存在均有失败提示。销售无内部财务记录和路径。

报表快照上限2 MiB，产物上限4 MiB，超限明确要求缩小范围分批导出，不静默截断记录。新生成格式由 `monthly-v1` 标识，旧冻结输出不强制改格式，旧worker兼容仍独立验证。

## 日志

`logs/<北京时间_唯一会话号>/runtime.jsonl`：每次顶层启动新目录，同次控制器/桌面/主机/账本继承会话ID；独立主机保留自身会话。事件带来源、时间、PID、会话，操作结果及原始文件系统错误可追踪。跨进程文件锁保护JSONL，不可写/锁超时不阻塞业务；重复事件60秒汇总，256项去重上限。每文件4 MiB，当前加4份轮转，即每会话约20 MiB日志上限；旧会话不自动删除。请求正文、令牌、密码和业务全量不写入，不逐行复制构建输出。没有新增日志UI。
