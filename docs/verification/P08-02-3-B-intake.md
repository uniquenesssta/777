# P08-02-3 B：4.23 接收与持久化

本阶段提供显式维护启用的 `receive_only` 接收基础。正式端保持原在线模式，不宣告离线正式入账；业务应用/安全合并在 C，本机保存与静默上传在 D。未操作现场 4.23/4.38，不新增正式 UI、Figma 或日志入口，不执行最终安装包及其构建准备验证。

## 实现

- 业务设备 a2 会话认证，校验账本、设备、主体、包权限与授权 epoch；密码维护、发行和节点会话不能上传离线业务。Ed25519 租约采用锁定的 ring 0.17.14，30 天到期；同请求重试返回原签名，续期保留 stream，显式恢复换 stream；价格摘要仅核对公共报价投影，避免用私有成本摘要提供猜测线索。
- 原件、状态、事件及将来的冲突/裁定/feed 表放在同一账本，schema 3 显式事务升级；默认新账本仍为 2。原件只追加，操作 ID 和 stream/sequence 唯一；在线业务及导出 request_id 双向检查，运行入口共用短写入顺序门，防止跨入口并发抢用 ID。202 在接收事务提交后返回，只表示可靠收件，不计中央金额。
- 同 ID/摘要返回原接收身份和最新状态；改正文保留首份、返回 409，另在限额内保留碰撞证据。乱序依赖等待，循环和跨订单/设备链拒绝；缺失前项超过 24 小时保全为 rejected。按操作游标重扫，重启不依赖内存队列，不以设备最高序号阻塞无关订单。
- 请求最多 1 MiB、32 项、单项 256 KiB；独立 4 个收件并发槽，原业务 8 槽保留；设备单在途请求、全局/设备速率限制、队列条数/原文体积/最小磁盘空间限制。租约及碰撞证据另有数量限额；达到上限拒绝追加，保留已有数据。
- 恢复写出/读取 `777-data-backup-v3`，兼容旧 v1/v2；完整主从快照用 schema 3 对应的新清单标识，队列变化即使金额 revision 未变也会发布新代。恢复包含公钥、原件、状态和依赖，不含签名私钥或启用配置；不能自动恢复接收/应用身份。
- 手动备份及每日交付使用独立 Service 视图和备份互斥锁，SMB 交付不占订单 Service 互斥锁；手动备份另有 1 个并发名额，不占普通业务 8 槽或收件 4 槽，收件不等待订单服务锁。在线抓取在本机账本写入保留锁内读取账本，并以同一导出连接/事务校验和复制导出记录、附件；返回后释放事务，再生成 Excel 和交付。开发者只读导入不获取写锁，不把共享目录当数据库。

## 启用边界

新增维护命令 `prepare-offline-intake` 只在 Host 已停止、owner 排他锁可取得且管理员认证成功时运行；通过 stdin 输入密码，不在命令行嵌入密码。正式启动不会自动执行此升级。升级前保留并验证 `private/ledger-before-offline.sqlite3`；已安装的 Rust worker 必须先在一次性 schema 3 探针库通过 inventory 核对，才允许迁移现有库。已有数据、服务/账本身份、证书及备份配置保留。

仅主服务器提供接收；从机不成为独立写入端，无自动升主。共享 `\\192.168.4.23\共享\backup` 仍仅备份目标。本阶段不发布现场升级操作单，避免把接收基础当成完整离线业务。
