# 开发者订单清理与文案修正（2026-10-21）

## 已接通行为

- 开发者工具新增“订单清理”：搜索淘宝 ID、微信号或订单号；每页 20 笔，逐笔确认删除，必填原因；明确显示连接和实际账本 ID。
- 删除是持久业务删除，非物理抹除：从业务视图和统计中移除，原始订单、修改快照和删除原因/时间/操作账号保存在不可修改的审计账本。“删除记录”可查，不提供抹除或恢复按钮。
- 原生客户端及 Host 都检查访问身份；正式端没有入口，自动设备凭据不能调用删除接口。账本 ID、防并发订单版本和原请求幂等检查均在 Host 落实；副本主机拒绝直接维护，不静默代转。
- `POST /v1/developer/orders/list` 读取现有订单或删除记录；`POST /v1/developer/orders/delete` 提交账本、请求 ID、订单、版本、原因。SQLite 即时事务同时提交作废投影、版本快照、删除审计、请求回执、账本版本及离线变更流，任何一步失败回滚。
- 保留现有 schema 与不可修改触发器，用 `delete_order` 审计作为持久删除标记；完整性校验仍重算删除前快照并核对审计关联。不会删除、修改旧的审计或订单原始数据。
- 冷查询、增量查询缓存、客户分组及利润统计一致排除已删除订单；全删测试客户后，新报价不会被无可选择的旧客户索引卡住。
- 离线回传的旧编辑/恢复不会恢复已删除订单，原始提案和冲突仍保留。主机发布删除版本，终端下载后即使有待上传修改也隐藏订单；未上传输入不被清除，过期下载不能覆盖删除标记。完整数据代及恢复备份均保留标记。
- 新财务报表及每日 Excel 阅读分表排除已删除订单。每日备份完整辅助表和 `.qbackup` 继续保留审计与原始数据；已经导出的 Excel/图片和历史备份不做追溯删除。
- 断线/不完整响应可复用同一请求重试；并发修改、目标账本变化或已删除时提供重新读取，不能用旧版本不断重复删除。
- 界面、错误消息和当前 Host/开发工具提示中的“管理员”改成具体语义：已发布的保存位置、内部核算、账本访问权限、维护人员、Windows 系统授权等。内部角色标识与真实权限检查保持，不因文案降低权限。Figma 节点见设计交接文件。

## 更新顺序

1. 开发电脑 `git pull` 后重新运行 `npm run dev`，获得删除入口和文案。
2. 开发电脑执行 `npm run package:host` 生成新版 Host 包。更新已部署的 Host 程序，保留 `host-local.json`、`Quote777Service`、`Quote777Hidden`，不要靠删业务文件夹升级。
3. 对已经是主机的 4.23，现有菜单 8 可以执行资源升级并保留账本/证书；仅覆盖 Host zip 或运行已有部署的一键启动不保证升级正在使用的原生二进制。不要在副本主机上用菜单 8 改角色；副本升级沿用既定保留角色流程。
4. 所有参与同步的 Host 都使用新版本；正式端重新封包更新，以识别删除标记并从离线列表移除，也更新这轮文案。旧正式端可能仍把记录显示为作废，不能据此认为同步已完整升级；Host 会阻止回传恢复。
5. 更新完成后每次删除订单不再需要重做 Host 或安装包。只在开发者工具选择当前主账本的订单执行。
