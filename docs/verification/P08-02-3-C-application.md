# P08-02-3 C：主服务器应用、合并与独立授权裁定

## 已实现

- **应用原子性**：显式 apply 后，由常驻 Host 后台逐项重验设备、租约、权限、规则、价格及依赖。业务变更、完整前快照、requests、审计、feed、终态回执及依赖唤醒同库提交；事务前故障不生效，事务后原 ID 读回原结果。普通在线写入共用 journal，不嵌套提交两次。
- **按单处理**：稳定订单/行/备注 ID 不因重传更换；乱序后继可靠等待，新到达 received 不受旧 waiting 游标限制，父项终态唤醒有界后继。冲突/拒绝保全，不阻塞其他订单，不按全设备序号一刀切。
- **去重与客户**：同操作重复不新增业务或输出任务；同客户不同外部订单号保留多单，唯一且兼容的客户候选可归集；非空外部订单号精确相同进入疑似重复，不按客户身份拼单。
- **保守三方合并**：可验证共同基础、稳定行 ID、无冲突的普通商品行及不同详情字段可合并；同一行/字段竞争、折扣关联变化、状态竞争或缺基础均保全。金额按各行不可变价格版本重算，不采信设备成本利润，不用最后收到者覆盖。
- **冲突与裁定**：原始候选及摘要不变，保存基础/当前版本引用；独立授权开发者可分页读取、保留当前、明确应用更正候选或将新单商品归并到同归属订单。核验目标版本及稳定裁定 ID，竞争裁定拒绝，重复裁定返回原结果。服务端裁定具有清晰 server_resolution 来源，不伪造设备认证。
- **权限与拉取**：裁定须真实密码维护会话和账本/恢复/用户 epoch 绑定的单独授权；正式设备、未授权 admin、发行及节点无此权限。确认 feed 使用主体/设备/包/能力及恢复 epoch 绑定的签名游标；按当前权限分块返回订单，销售不取得成本利润、他人订单、原冲突或技术原因。
- **恢复兼容**：保持 B 的 schema 3 和结构哈希；新增已应用请求、裁定及版本引用交叉核验，v3 恢复和复制保留完整事实。启用前探测已安装 Ledger worker 对完整备注/状态前快照的兼容性；旧 worker 不符先停止。裁定授权不进入备份或恢复。

## 维护与正式端边界

新增的是主机维护 CLI `enable-offline-application` 与 `set-offline-reviewer`，均需停服排他锁和真实维护管理员密码；不是正式端设置，不自动运行、不在现场启用。命令秘密仅通过既有 stdin 路径读取，不写入本证据。

正式端界面、包权限选择、登录/退出、连接提示和问题日志策略均未改动。内部完整快照保留备注/状态基线，现有正式端“修改记录”仍只投影既有 save_order 业务编辑。没有本轮 Figma 或最终母/子包、构建准备验证。

共享 `\\192.168.4.23\共享\backup` 仍只接收备份；业务和合并写入 Host 本机 ledger。没有访问现场共享路径、同步副本或迁移三个 Quote777 目录。

2. 新增 C 业务/权限/恢复/进程故障用例：稳定身份及重复入账防护、乱序重启与唤醒、多端独立修改、金额/折扣冲突、作废竞争、客户多单、保留旧价、授权隔离、裁定竞争/重放、分块越权、撤销后保全、v3 备份/复制/Excel、应用与裁定提交前后进程崩溃。
