## 使用方式

母版进入Excel记录，打开文件，在利润明细中选中一行：下方显示该稳定订单编号、版本、有效/作废状态、只读备注历史与操作记录。选择同一订单的不同明细仍指向同一订单；切换订单时，未保存的备注草稿分别保留在当前会话，不写入文件。关闭窗口后草稿不持久保存。

追加备注只增加新记录。更正采用另一条说明，保留旧备注；历史区不可编辑，追加区不会载入历史供覆盖。文件列表的“历史备注预览”只是摘要，旧文件说明不会被附给最后一个订单。

作废或恢复前填写原因，再点击相应按钮。确认框显示完整订单ID、读取版本、文件名、原因及金额变化；取消不改文件，也不清除原因。选中订单/读取版本在确认期间变化时拒绝操作。确认后仍在完整文件锁内检查最新文件哈希和订单版本，外部插删/重排行或其他母版写入使旧页面拒写，刷新后重新选择。

有效单可追加备注或作废；作废单可查看历史、恢复。作废后销售视图隐藏该单，日汇总排除其金额；恢复改变原单状态并重新计入一次，不复制明细、不增加新订单。原金额、明细ID、原始请求、备注、价格与输入检查记录保留。空客户/空订单号不影响稳定ID管理。无稳定ID的旧记录保持只读，整文件物理删除继续停用。

## 数据与接口

| 接口 / 数据 | 当前契约 |
| --- | --- |
| `quote_files.orders.OrderView / order_views` | 独立于Tk的按订单投影，包含版本、状态、备注、请求操作/时间/原因、输入检查及价格快照；关联表按ID分组，不按行号、客户或时间猜归属 |
| `edit_order` | 明确支持append_remark / void_order / restore_order；未知操作拒绝。备注或原因须1～4096字符，状态与expected_revision符合后整单版本加1 |
| `_edit_order(..., reason=..., target=...)` | owner线程捕获目标，确认后核对捕获值；操作/订单/版本/内容绑定request_id，沿用哈希CAS和回执优先回放，同一请求不会重复金额或备注 |
| `订单备注` | 保留原请求ID、订单ID、备注三列；request_id作为唯一追加记录身份，提交时间和版本来自同一事务回执；字符串强制文本 |
| `_写入事务` | 新作废/恢复结果记录previous_state、state、reason及order_revision；保留已有提交时间、请求及全局版本。旧作废回执缺原因显示“旧回执未登记原因”，不补造原因 |
| `输入问题` | 兼容旧第4行六列表头；新增订单追加时扩展为原六列加订单ID/请求ID。旧诊断单元格保留，旧行身份留空，不猜归属；新行在同一事务绑定原始追加请求 |
| `订单价格快照` | 保留03逐单快照，作废/恢复不删除、重建或改价；关联状态由原订单状态决定，不维护容易失步的副本状态列 |
| 关联校验 | 已知备注、快照、新输入行须有匹配订单/对应操作回执；孤立关联、部分身份及重复备注请求阻止写入，原件不替换；未知附表仍只读 |

请求已经保存但列表/工作表刷新失败时，提示“已保存，刷新失败”及请求编号，不当作提交失败。结果不明保留原因/备注/原请求，先在详情页或连接区点击“检查上次写入”；查到提交回执后刷新该单，明确未提交可用同一请求重试，未知或无回执继续保留待核查状态。变更操作内容不能绕过未核查请求。

当前母版会话没有服务认证，回执不是认证操作者签名；子版直接调用备注/作废/恢复仍拒绝。本人备注授权、成本隔离和服务审计由P05实施。恢复按钮是恢复作废订单，不是从文件备份覆盖账本；`.777-recovery`写前副本继续保留，E盘根独立隐藏备份及恢复演练按P05/P08实施。

所有共享写端应一起更新到当前阶段版本。旧03代码不能识别恢复回执或扩展输入表，不能混用旧写端；原历史文件的已知六列输入表仍可读写，新记录才补明确关联。原26列、金额核心、黄金目标、P01归档及历史实测报告保持原值。
