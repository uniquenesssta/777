## 2. 数值技术建议（P02前采纳）

唯一业务金额规则仍在[迁移契约](../MIGRATION_CONTRACT.md)；本节解释机器profile的选择依据。容量是可审核的首期技术上限，并非已从9项真实配置证明业务最大需求。P02开始前若需更大范围，先改profile/边界期望/版本和证明，不在失败后扩大上限。

| 参数 | 建议与明确行为 | 黄金/检查依据 |
| --- | --- | --- |
| 普通字段 | 最终值0～1,000,000,000；规范值最多12位小数，尾随0不算额外精度；普通字面量同范围/小数位 | G22～25与G40～42；尺寸/单价不先压为两位 |
| 原文与表达式 | 原文256字符，单位处理后80字符；AST最多64节点/递归深度16；十进制/科学记数法字面量指数−12～9；只允许原四则、余数及一元正负 | 普通数值/百分号沿用原单位归一化；布尔、名字、调用、乘方、空必填、除零均拒绝；只允许空K默认1 |
| 表达式除法 | 每个`/`节点ROUND_HALF_UP至12位小数，再进行后续节点；不得先经float；精确整数商/余数决定半位，避免先以低精度近似后再次舍入 | G19：1/3→0.333333333333；G20：1/3×3→0.999999999999，乘0.005结算为0.00；该变化属于技术建议 |
| 其余运算 | 加减乘和余数精确；每节点绝对值≤10^45、规范小数位≤60，最终字段仍需满足12位和非负范围；超限拒绝，不能静默截断 | 包括运算中间为负但最终非负的表达式；余数为a−floor(a/b)×b，保留原Python除数符号语义，不能直接套Decimal的不同余数规则 |
| 折扣 | 数字0～100，可有尾随%；最多12位小数；折扣结算时百分比除100精确，不套普通表达式的12位除法舍入 | E05/E06、G28；100与0边界，非法表达式及超过100拒绝；折扣显示保存足够精度 |
| 金额/累计 | 分整数绝对值≤9,223,372,036,854,775,807；行销售/成本/利润和每次累计销售/成本/利润均检查；0显示0.00；对负利润/折扣使用对称上限 | G23/G24为边界，G52/G53越界；中间累计超限不能等后来折扣再放行 |
| 单订单明细 | 最多10,000行，空列表不提交；容量错误同样整单阻断 | 数据规模与边界检查；这不是历史目录最多10,000行，历史查看须分页完整可达 |
| Python/Rust表示 | Python候选Decimal精确运算context.prec=256；除法显式舍入；Rust表示/依赖由P06证明所需范围，不能假定任意固定精度十进制库即可满足 | 合法中间值最多46整数位+60小数位＝106位；两个这样的操作数乘积最多212位，256为单节点精确计算留余量；节点后立即检查容量。面积五因子乘积最多10^45/60小数位；IPC规范十进制字符串，最终金额以分字符串跨JS边界 |

禁止把context精度当唯一溢出检查。每节点先限制输入/资源，再检查结果；非除法运算若发生Inexact是实现错误，不能继续当合法结果。过大原文、指数或树深先拒绝，不先构造无限规模数再校验。规范化字符串保留原文另字段；未被单件使用的高宽无需解析。

静态金额沿用P01-02已确认金额或本次人工声明销售/成本，利润和利润率由这些声明金额计算后固定；运行时用不同的有理数路径交叉核对。测试期间曾把`5 % -3 + 3`的检查期望写为1，正确值为2，已改正检查期望；最终回归通过，没有修改原业务程序或已批准金额。

技术参考：[Python 3.12 Decimal](https://docs.python.org/3.12/library/decimal.html)、[Fraction](https://docs.python.org/3.12/library/fractions.html)、[余数与除法](https://docs.python.org/3.12/reference/expressions.html#binary-arithmetic-operations)。文档与当前Python 3.12行为核对，仅指导实现；本次未选择或引入Rust依赖。
