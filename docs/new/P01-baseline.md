# P01 基线、业务规则与验收样本

状态：待启动。前置：本轮审计文档已交付。拟议分支 `stage/p01-baseline`，启动时确认实际基线；本次仅在plans编写任务书。主入口：[主任务书](../MASTER_PLAN.md)。

目标：明确真实部署、金额规则和角色能力，把正确现状与已知缺陷分开，建立以后Python/Rust共用的验证材料。范围不包含修复业务源码、重做UI或迁移真实账本。

## Atomic Tasks

| ID | 输入/范围与交付 | 可执行验收 | 恢复与边界 |
| --- | --- | --- | --- |
| P01-01 | 核对两份blob、运行环境、实际Python/openpyxl/Pillow版本与启动方式；登记图标/打包资源、依赖清单、可复现测试入口 | 干净Windows环境能按记录启动两版；缺依赖/资源清楚报告；不因此新建Linux/macOS门槛 | 保留原环境与原包；新增依赖先评估，不直接升级用户机器 |
| P01-02 | 确认舍入/负数/小数数量/零利润率、价格生效、子版成本可见性、删单/备注权限及订单查询范围；冻结迁移契约v1 | 用普通商品、折扣、分位边界举例由用户确认；权限矩阵覆盖管理员/销售/未认证及直接接口调用 | 未决项阻塞依赖实现，不把建议当决定；记录决策及影响 |
| P01-03 | 收集脱敏config、新旧Excel及真实目录映射；确认Windows版本、SMB主机、写端数量、备份/运维责任和服务拓扑 | 原件哈希、只读副本、schema分类、未知格式名单齐全；证明母子目录实际同源或记录差异 | 不向仓库提交客户真实信息/凭证；原件不改；服务方案未确认不部署 |
| P01-04 | 建立黄金样本、格式样本、性能基线方案与Windows验收清单；复用audit隔离证据 | 正确样本可无UI执行；旧缺陷有新期望；数据集包含100/1000/10000条明细、10/100/1000个文件（合成），记录冷暖条件及指标 | 大集规模可在执行前按真实容量确认；不能事后调整掩盖失败 |

## 阶段退出门槛

- P01-01至04均有证据；确切金融规则、角色权限、部署方式已确认。
- 至少覆盖面积、单件、K、连续折扣、折扣后加商品、输入错误、零收入、精度边界、同秒不同单、损坏表、旧字段和备注。
- 性能指标包括UI心跳、Excel打开次数、worksheet扫描次数、冷暖耗时、内存、并发冲突结果；本阶段记录当前缺陷，不要求原版先全部通过。
- Windows现状如无法启动应作为阻塞定位，不伪造基线；不满足前置则留在now，不进入P02。

验收记录（执行时填写）：实际分支/基线、决策清单链接、样本哈希、命令/环境、真实结果、未验证项、用户验收、下一步。
